# Quickstart: Marketplace Release Readiness

How to produce, verify, and publish the release. Steps marked **(maintainer)**
are outward-facing actions performed/authorized by the repo owner.

## 1. Build and stage the published bundle

```bash
npm run build-local          # spicetify-creator --out=dist --minify
# stage the installable folder into the tracked dir:
mkdir -p marketplace/dedup
cp dist/index.js dist/style.css dist/manifest.json marketplace/dedup/
```

`marketplace/` is tracked (not gitignored); `dist/` stays gitignored. A
convenience `npm run stage:marketplace` script may wrap the copy.

## 2. Author the root listing manifest

Create `manifest.json` at the **repo root** (distinct from
`marketplace/dedup/manifest.json`) per
`contracts/listing-manifest.schema.json` and `research.md` D3:

```json
{
  "name": "Dedup",
  "description": "Find and remove duplicate tracks from your Liked Songs and playlists, safely, from inside Spotify. An in-client port of José M. Pérez's spotify-dedup.",
  "preview": "preview.png",
  "main": "marketplace/dedup/index.js",
  "readme": "README.md",
  "tags": ["dedup", "duplicates", "library", "playlists", "liked-songs"],
  "authors": [
    { "name": "atb2903 (port)", "url": "https://github.com/atb2903" },
    { "name": "José M. Pérez — original spotify-dedup", "url": "https://github.com/JMPerez" }
  ]
}
```

## 3. Capture the preview image (maintainer + live client)

Run the live client, open Dedup, Load, and capture a clean screenshot of the
loaded list (or a scan result). Commit it as `preview.png` at the repo root.
(Driver protocol: agent pushes/restarts the client and hands a checklist; the
maintainer captures.)

## 4. Validate

```bash
npm run test:coverage        # validator + integration test must pass at 100%
npm run typecheck
```

The integration test loads the real root `manifest.json`, validates it, and
asserts `preview.png`, `marketplace/dedup/index.js`, and `README.md` all resolve,
and that `marketplace/dedup/` holds index.js + style.css + manifest.json.

## 5. Release hygiene

- Add root `LICENSE` (MIT) with a `spotify-dedup` attribution line.
- `package.json`: set `"version": "1.0.0"`, remove `"private": true`.
- Add `CHANGELOG.md` with a `1.0.0` entry crediting the upstream project.
- Rewrite `README.md` for end users: what it does, **manual install steps**
  (below), usage, a **Credits** section linking `JMPerez/spotify-dedup`, and a
  **Generative AI disclosure** section (see below).
- Add the AI disclosure line to the `CHANGELOG` 1.0.0 entry too.

### Generative AI disclosure (for README + CHANGELOG)

> Built with Claude Code (Anthropic's Claude) using the Spec Kitty spec-driven
> workflow. Code, tests, and documentation were generated by AI under human
> direction and review.

### Manual install steps (for the README)

```bash
# Copy the app folder into Spicetify's CustomApps directory, e.g.:
#   Linux/macOS: ~/.config/spicetify/CustomApps/spicetify-dedup
#   Windows:     %appdata%\spicetify\CustomApps\spicetify-dedup
spicetify config custom_apps spicetify-dedup
spicetify apply
# Spotify restarts; a "Dedup" entry appears in the sidebar.
```

## 6. Verify install (DoD — live client)

Manually install `marketplace/dedup/` as above and confirm the Dedup page renders
**styled** and load/scan/remove behave exactly as the pre-mission build. Capture
the verification artifact.

## 7. Publish (maintainer)

```bash
git tag v1.0.0               # version must match package.json + CHANGELOG
git push origin main --tags
```

Then, in **GitHub repo settings → Topics**, add `spicetify-extensions`. The
crawler discovers the repo on its own schedule (no wall-clock guarantee — out of
scope per NFR-005/C-006).

## Done when

- SC-001: validator green against the real root manifest; all paths resolve.
- SC-002: manual install yields a working, styled Dedup app matching prior
  behavior (verification artifact captured).
- SC-003: LICENSE present; README end-user ready; CHANGELOG + tag both `1.0.0`;
  no prototype-status language remains.
- SC-004: the `spicetify-extensions` topic step is documented; maintainer sets it.
- SC-005: release docs state the two manifests' distinct roles.
- SC-006: the generative-AI disclosure is present and plain in README + CHANGELOG.
